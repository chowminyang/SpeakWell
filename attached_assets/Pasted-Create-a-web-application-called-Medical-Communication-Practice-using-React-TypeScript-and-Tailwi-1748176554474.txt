Create a web application called "Medical Communication Practice" using React, TypeScript, and Tailwind CSS. The app's primary goal is to help medical professionals practice their communication skills for common medical scenarios in either Simplified Mandarin Chinese or Bahasa Melayu. The application will feature AI-generated scenarios, user input via text and speech, AI-driven evaluation and feedback, and a gamified progression system.
I. Core Functionality & Features:
Password Protection:
The application must be initially locked. Access is granted upon entering a correct, hardcoded password (e.g., "humeaine").
Language Selection:
After successful authentication, the user must be prompted to select their practice language: "Simplified Mandarin Chinese" or "Bahasa Melayu."
AI-Powered Scenario Generation (Gemini API):
Upon language selection, the app will fetch an initial medical scenario.
Scenarios are presented in English and describe a situation the user needs to communicate to a patient in the selected foreign language.
Scenarios must be generated by the Gemini API (use model gemini-2.5-flash-preview-04-17).
The AI prompt for scenario generation should request only the concise English text the doctor should say (e.g., "Inform the patient they have mild flu and need to rest." NOT "Your task is to tell the patient...").
Scenarios should be brief (1-3 short sentences).
Implement difficulty levels for scenarios: 'Easy', 'Medium', 'Hard'. The selected difficulty influences the complexity of the generated scenario.
The app must keep a list of recently used scenarios (e.g., last 5) and include them in the prompt to Gemini to ensure variety and avoid immediate repetition.
User Input Methods:
Text Input: A textarea where users can type their response in the selected foreign language.
Speech Input & Transcription (Gemini API):
A microphone button to allow users to record their response.
The app must request microphone permission.
Record audio (e.g., in webm/opus format).
The recorded audio blob must be converted to a base64 string.
Send the base64 audio data and the target language to the Gemini API (model gemini-2.5-flash-preview-04-17, using multimodal capabilities) for transcription. The prompt should specify the language of the audio.
The transcribed text (in the foreign language) should populate the textarea.
Speech Translation for Review (Gemini API):
After successful transcription, the transcribed foreign language text should be sent to the Gemini API (model gemini-2.5-flash-preview-04-17) to be translated into English.
Display this English translation to the user (e.g., "Your speech (translated to English): ...") so they can verify the transcription's accuracy before submitting for evaluation.
AI Evaluation and Feedback (Gemini API):
When the user submits their attempt (from text or transcribed speech):
Send the original English scenario and the user's foreign language attempt to the Gemini API (model gemini-2.5-flash-preview-04-17).
The prompt to Gemini must instruct it to act as a language tutor and return its response strictly as a JSON object containing:
attemptScore: A numerical score from 1 (poor) to 5 (excellent) rating the user's attempt on accuracy, grammar, completeness, and appropriateness.
feedback: Constructive feedback in English (2-3 sentences) on the user's attempt.
modelAnswer: An ideal model answer in the selected foreign language.
For Simplified Mandarin Chinese, this model answer must include Pinyin in parentheses after the Chinese characters (e.g., "你好 (Nǐ hǎo)"). The Gemini prompt should explicitly request this.
explanation: (Optional but helpful) A brief English explanation of a key grammatical point or vocabulary choice from the model answer (1 sentence).
The application must parse this JSON response. Be prepared to handle JSON strings that might be wrapped in markdown code fences (e.g., json ...).
If the user's attempt is empty or clearly not in the target language, the AI should be prompted to return an attemptScore of 0 and appropriate feedback.
Text-to-Speech (TTS) for Model Answer:
Provide a button to allow users to hear an audio playback of the modelAnswer using the browser's SpeechSynthesis API. Ensure the correct voice/language code (e.g., "zh-CN", "ms-MY") is used.
Handle cases where TTS might not be supported or voices are unavailable.
Gamification & Progression:
Score: Users earn points based on their attemptScore (e.g., attemptScore * 10).
XP and Levels: Users earn Experience Points (XP) based on their attemptScore (e.g., attemptScore * 20).
Levelling Up: When XP reaches a threshold, the user levels up.
XP to Next Level: The XP required for the next level should increase progressively (e.g., initial_xp_needed + (current_level - 1) * xp_increase_per_level).
Difficulty Unlocking:
'Easy' difficulty is available from Level 1.
'Medium' difficulty unlocks at a certain player level (e.g., Level 3).
'Hard' difficulty unlocks at a higher player level (e.g., Level 5).
The UI should clearly indicate locked/unlocked difficulties.
Display a "Level Up!" message when a user levels up, potentially highlighting newly unlocked difficulty levels.
Application Flow & Navigation Controls:
"Submit Attempt" button: To send the user's input for AI evaluation.
"Try This Scenario Again" button: Appears after feedback is shown, allowing the user to re-attempt the same scenario.
"Next Scenario" button: Fetches a new AI-generated scenario based on the current language and difficulty. This button might also function as "Skip Scenario" if no attempt has been made on the current one.
"Change Language" button: Allows the user to return to the language selection screen.
State Persistence:
Use localStorage to save the user's state, including:
Authentication status (isAuthenticated).
Selected language (selectedLanguage).
Player statistics (playerStats: score, level, XP, XPToNextLevel).
Current scenario (currentScenario).
List of previous scenarios (previousScenarios).
Chosen difficulty (chosenDifficulty).
Load this state when the app starts to allow users to resume their sessions.
II. UI/UX Design & Aesthetics:
General:
Clean, modern, professional, and intuitive user interface.
Fully responsive design, adapting to various screen sizes (mobile, tablet, desktop).
Utilize Tailwind CSS for all styling.
Provide clear visual feedback for loading states (e.g., spinners while waiting for API responses), errors, and interactive elements.
Use icons where appropriate (e.g., microphone, play/stop for TTS, submit, navigation).
Screens:

IV. Specific Implementation Guidelines:
Gemini API Integration:
Initialize the GoogleGenAI client instance using new GoogleGenAI({ apiKey: process.env.API_KEY }).
Use ai.models.generateContent() for all text-based and multimodal (audio + text) generation tasks.
For the evaluation service, ensure the config for generateContent includes responseMimeType: "application/json".
Audio Handling:
Use navigator.mediaDevices.getUserMedia({ audio: true }) to request microphone access.
Use MediaRecorder API. Attempt to use preferred MIME types like audio/webm;codecs=opus or audio/ogg;codecs=opus, falling back to browser defaults if necessary.
Collect audio data in chunks and create a Blob.
Convert the Blob to a base64 string before sending to the Gemini API.
Error Handling: Implement graceful error handling throughout the application. Catch errors from API calls, media device access, TTS, and localStorage operations. Display informative messages to the user.
Accessibility (A11y): Make reasonable efforts to ensure accessibility by using semantic HTML and ARIA attributes where appropriate (e.g., for buttons, inputs, progress bars, alerts).
Code Quality: Write clean, readable, well-organized, and performant code. Use TypeScript effectively for type safety.
